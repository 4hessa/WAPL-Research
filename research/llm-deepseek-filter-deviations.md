# Stage 77 deviations from the protocol

Amendment 1 (decontamination in Qwen2.5 tokenization) was made before any stage-77 code was committed or any model was run, after a data-only dry run; it is recorded in the protocol and is not a deviation of the run.

## 1. The calibration stopped the run at the N range check; amendment 2 caps N at 1,992 (25 November 2026)

**What happened.** The first launch (commit 96e2a21, NVIDIA L4) built the population exactly as the dry run (pool SHA-256 f239a0dd..., 41,418 and 18,697 eligible web chunks, 5,337 eligible target rows), then calibrated: c_r = 0.16287 s, S = 872.31 s at scoring batch 8 (no out-of-memory), S / c_r = 5,355.8 random steps, N = floor(7400 - 5355.8) = 2044. The protocol required 1000 <= N <= 1992, so the runner exited ("N = 2044 outside [1000, 1992]: design infeasible") before any training run or evaluation. The journal (/content/stage77-journal/journal.jsonl; snapshot f5a1edd on colab/stage77-journal) holds one environment entry and the calibration only.

**Why.** B = 7400 was chosen from the smoke-2 estimate S = 903.5 s, extrapolated from scoring 2048 chunks; the full scoring of 7968 chunks took 3.5% less. The margin left below 1,992 (about 180 steps) was smaller than this error (234 steps).

**What was decided, before any outcome existed.** The owner chose amendment 2 (commit 4089e83): N = min(N_uncapped, 1992) = 1992, so that one pass over a kept set made entirely of QA chunks is possible (QA margin 0). The alternatives were raising the bound (N = 2044, at least 52 web chunks kept, QA share at most 0.975) and lowering B with a new calibration. Code, tests and audit were updated (commit 25edd50).

**Effect.** The filter is charged S (5,355.8 random steps) plus 1,992 updates = 7,347.8 of B = 7400; 52 charged steps (0.7% of B) are unused, while random trains 7400 updates. The equal-cost contrast is therefore slightly conservative against the filter. The calibration is not repeated: the journaled entry (updates = 2044, the uncapped value) is kept, and the resumed runner recomputes N = 1992 from the journaled costs. The resumed process appends a second environment entry (resumed_runs 0).

## 2. Lost machine during the run; resumed on a new Colab machine (26 November 2026)

**What happened.** The Colab machine running stage 77 was lost mid-run. Its last journal snapshot on branch `colab/stage77-journal` is commit `9fbfd7f` (20261126T014110Z, "7 finished runs"). Anything the machine wrote after that snapshot is lost.

**How many runs had finished.** The snapshot journal (SHA-256 `717732b6...`) holds 10 complete lines: the first environment entry (`resumed_runs` 0), the calibration (NVIDIA L4, c_r 0.16287 s, S 872.31 s, scoring batch 8, N_uncapped 2044), the second environment entry from deviation 1 (`resumed_runs` 0) and **7 finished runs**: seed 37700 (random, align_once, random_once), seed 37701 (align_once, random_once, random) and seed 37702 random_once, in the protocol's run order. This matches the commit message (only entries of kind `run` are counted) and the last line of `results/stage77-interim/run.log` ("7/12 runs complete"). The next run in that order, seed 37702 random, was in progress or had not started when the machine was lost. It is restarted from step 0 with the same seed and schedule, as stage 76 deviation 1. If it or a later run finished on the old machine but was never snapshotted, its result is lost and the run is repeated. Whether a run is repeated depends only on what the snapshot journal contains, never on outcomes; no outcome from the lost machine was read.

**What was re-established on the new machine, before any outcome was read.**

- Device: NVIDIA L4 (the calibration's device type; the runner refuses any other type), driver 580.82.07. This may be a different physical GPU from the one that produced the calibration and the first 7 runs.
- Software: torch 2.14.1+cu130, CUDA 13.0, Python 3.13.16, as journaled. The image came with transformers 5.22.1, so the protocol's pins (transformers 4.46.3, tokenizers 0.20.3, huggingface_hub 0.26.2) were reinstalled before any code ran.
- Downloads at the pinned revisions: deepseek-ai/deepseek-llm-7b-base `7683fea` (both weight files), Qwen/Qwen2.5-1.5B `8faed76` (tokenizer files only, amendment 1), FineWeb-2 `af9c133` (kept and removed files), ArabicMMLU `7aa530e` (All/dev.csv, All/test.csv).
- `tools/verify_llm_deepseek_filter_resume.py` (new, commit `2c8313f`; log `results/llm-deepseek-filter-resume-verification.log`): both weight-file hashes, the Qwen tokenizer hash, the four data-file hashes, and every population field (QA chunks and digest, web eligibility and decontamination counts, web document indices, pool digest, target eligibility counts and the 512 target items, both tokenizer hashes) equal the journaled calibration; the calibration device equals this device; N_uncapped = floor(B − S / c_r) = 2044 and N = min(2044, 1992) = 1992 (amendment 2). For the 7 finished runs: unique, a prefix of the protocol order, and each run's schedule digest, align_once kept set (recomputed from the journaled scores) and digest, random_once subset digest, QA shares, random-arm QA draws, views per chunk and checkpoint keys match. 34 checks, all pass. The tool prints pass/fail only.

**What was not changed.** The calibration is reused from the journal (no recalibration), as the resumption rule requires. Design, run order, seeds, schedules, evaluation and code are unchanged. The restarted process appends a third environment entry (`resumed_runs` 7), which marks the restart. The working journal is restored at `/content/stage77-journal/journal.jsonl` (byte-identical to the snapshot) and the runner keeps copying it and the run log to `colab/stage77-journal` after every finished run.

**Possible effects.** Per-step and scoring times on the new machine may differ from the calibration; they are journaled per run and reported, but N stays 1992. Bitwise equality across two physical L4 GPUs is not guaranteed; the remaining 5 runs (seed 37702 random and align_once, all of seed 37703) run on the new machine. The audit's GPU checks (self-scores and step-50 replays of seed 37700, produced on the old machine) therefore also test cross-machine reproducibility; their outcome will be reported either way.
